## 0. 先说结论

**你要的"那个"大概率是 `bylingfeng/LF.SleepCalculator`。**

## 1. 核心算法（复刻的关键就这一段）

所有这类项目本质是同一个公式，差异只在参数和展示：

```
候选时间 = 基准时间 ± (入睡潜伏期 + n × 周期长度)

周期长度   默认 90 分钟（个体实际 80~120）
入睡潜伏期 默认 10~15 分钟（可调 0~60）
n          睡眠周期数，推荐 4~6，多数实现展示 3~6
```

两种模式：
- **何时睡觉**：拿到起床时间，往回推 → `睡觉时间 = 起床时间 − (潜伏期 + n×90)`
- **何时起床**：拿到入睡时间，往后推 → `起床时间 = 入睡时间 + (潜伏期 + n×90)`

质量分档（各项目叫法不同，共识一致）：

| n | 时长 | 分档 |
|---|---|---|
| 6 | 9.0h | 充足 / optimal |
| 5 | 7.5h | **最佳**（多数人的甜点） |
| 4 | 6.0h | 勉强够 / good |
| 3 | 4.5h | 生存线 / fair |

LF 版的实际实现（原文摘录，`i` 取 1~6，标记 `isOptimal = i === 5 || i === 6`）：

```javascript
for (let i = 1; i <= 6; i++) {
    let d = new Date(base);
    let offset = fallMin + i * 90;
    if (mode === 'wake') d.setMinutes(d.getMinutes() + offset);
    else                  d.setMinutes(d.getMinutes() - offset);
    // ...排序、渲染，i===5||i===6 打绿色高亮
}
```

我已经把这段整理成可直接调用的模块，见同目录 `sleep-core.js`（含 6 种能力的实现 + 自测用例）。

## 4. 复刻技术选型

| 目标形态 | 推荐起手 | 理由 |
|---|---|---|
| **最快出成品（Web/PWA）** | 抄 LF.SleepCalculator 骨架 | 单文件、零构建、闹钟跨端那套现成，改改就能上线 |
| **小程序** | LF 的逻辑 + uni-app/Taro 重写 UI | 算法只 20 行，UI 层随意换；中文时段标签直接复用 |
| **安卓 App** | Sleepwell（RN+Expo）或 michiru233/SleepCycle（Kotlin） | 前者功能最全，后者中文+闹钟联动最完整 |
| **带数据闭环** | plees-tracker / HealthLog 的记录层 + LF 的计算层 | 计算器只能算"打算"，记录能算"实际" |

License 风险提示：`bhwarren/SleepCalculator` 是 GPL-3.0，有传染性，**商用别碰**；LF、Sleepwell 等是 MIT/自定，相对安全，但逐个仓库都要确认 LICENSE 文件。

## 5. 融合创意方向（11 条，按落地难度排）

1. **睡眠负债账本** —— 借鉴 `wei011/sleep-debt-calc`：累计债务 + 周末补觉效果 + 社会时差，给"继续熬 / 周末狂补 / 规律作息"三种活法的对比。这是最能拉开差距的点，纯计算器做不到。
2. **咖啡因截止线** —— 借鉴 `sethll` / `Alpha-Park`：输入今天喝咖啡的时间，按半衰期倒推"几点前必须停"，直接说人话。
3. **时型问卷校准** —— MEQ 晨型/夜型问卷 → 自动调整周期长度和潜伏期，而不是所有人默认 90/15。
4. **睡眠相位时间轴** —— 把一夜画成横向色带，标出深睡/REM 段，让"醒来点落在浅睡"变成肉眼可见。
5. **"现在该干吗"** —— 基于当前时间实时算：还能睡 X 个整周期 → 建议躺下 / 建议直接熬到某个点。
6. **闹钟联动** —— LF 已有 iOS 快捷指令 / Android intent / 华为 `hwclock://` 三套，直接复用，这是最容易出效果的一步。
7. **日落 + 光照提示** —— 结合本地日落时间提醒"睡前 2h 开始降蓝光"。
8. **真实数据回填** —— 接 Health Connect / Apple Health 读实际入睡时间，反推你的真实潜伏期，自动校准。做完这条就从"玩具"变成"工具"。
9. **轮班/倒班模式** —— 夜班、三班倒人群的睡眠窗口推荐，是现有产品普遍忽视的空白。
10. **伴侣作息对齐** —— 两人各输作息，推荐共同入睡窗口，社交传播属性强。
11. **Agent 化** —— 做成 Skill/MCP，让 AI 助手一句话算（`Alpha-Park` 和 `dungnotnull` 已经在这么做了，这是最新的形态）。

## 6. 必须知道的坑

- **90 分钟是均值不是定律**：个体在 80~120 分钟之间，固定 90 会累积误差。想专业就得给可调 + 用真实数据校准。
- **入睡潜伏期是关键差异点**：sleepyti.me 当年最大的槽点就是没算这个，导致"几点睡"和"几点睡着"混为一谈。这一点务必保留可调。
- **多数是练手项目**：代码质量参差，很多只有 0~5 星，别指望直接拿来当生产基座，主要是抄算法和交互。
- **别做成纯计算器**：这个赛道已经饱和，免费工具一大把。差异在数据闭环和场景化。
