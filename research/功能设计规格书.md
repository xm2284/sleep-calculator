## 0. 定位：先划清差异线

市面上所有睡眠产品的功能可以归成三类：**监测类**（手环/麦克风/声呐）、**内容类**（白噪音/冥想）、**计算类**（就寝时间）。这三类都已经是红海。

我们要做的是第四类：**证据可查 + 行为闭环**。

具体差异点：

| 维度 | 市面普遍做法 | 我们的做法 |
|---|---|---|
| 结论来源 | 不告诉你 | **每条建议挂证据等级（A/B/C）+ 可点开的原始出处** |
| 夜间监测 | 核心卖点（要硬件/麦克风） | **不做**（静态站也没法做），改成白天可执行的计算与规划 |
| 内容库 | 拼白噪音数量 | **不做音频库**，做「什么时候该做什么」的时机引擎 |
| 数据闭环 | 记了但不给推理 | 记录 → 算睡眠效率 → **自动调睡眠窗口**（iCANSleep 的做法） |

学术上有篇 SleepKit（KU Leuven）把设计目标写得很清楚，直接拿来当产品原则：

- **G1** 让用户能自己判断睡眠质量好不好（不是给一堆术语）
- **G2** 让用户明白哪些习惯在影响睡眠
- **G3** 促成行为改变

其中一句话值得刻在首页上：**「大多数人无法从睡眠图或各阶段时长里推出任何结论」**——所以缺的从来不是数据，是**解释**。

3. **蜗牛睡眠的社区/分享**是增长引擎，但也是内容监管成本。静态站阶段不建议碰

### 1.4 学术设计论文（最有价值的三篇）

**① SleepKit（KU Leuven，硕士论文）**
- 首页顶部就是**睡眠卫生建议清单**（运动、咖啡因、小睡、深夜进食、酒精、吸烟、屏幕、放松），**按当前时间只显示相关的几条**，配时间轴可左右滑动看过去/未来建议
- 睡前填一个 **yes/no 打卡**（今天做到了哪几条），这是最低负担的自我反省机制
- 数据区配**描述性总结**（正面/负面因素），而不是只给图
- 核心洞察：**「过度睡眠和睡眠不足一样有害」**，以及**「保持规律作息（包括周末）比单次调整更重要」**

**② iCANSleep（JMIR，癌症幸存者失眠）**
- 唯一一个把 **CBT-I 睡眠限制疗法算法化**的开源设计文档
- 核心逻辑（**可直接抄进产品**）：
  - 用户一周至少填 5 天日记才推进下一模块
  - 睡眠效率 **≥85%** → 表扬 + 鼓励，建议睡眠窗口 **+30 分钟**
  - **75%–85%** → 维持窗口，处理问题区域
  - **<75%** → 睡眠窗口 **−30 分钟**，但**永不低于 5 小时**
- 通知只保留两条：早上提醒填日记、睡前提醒放松
- 徽章：连续打卡徽章 + 睡眠改善奖励
- 隐私：只收必要数据、无广告、不卖数据、本地 SQL

**③ SomniBot（黑客松设计项目）**
- 「**渐进式个性化**」流程：快速自评（5 题）→ 结果摘要 + 建议 → 用户选择深挖「追踪症状」还是「常见原因」
- 用户研究结论：**80% 用户想要私有可信的睡眠伴侣**，不信任通用搜索和泛用聊天机器人
- 三层信息架构：主功能 → 模块动作 → 微交互

### 1.5 行业标准：Consensus Sleep Diary（Carney et al. 2012）

AASM 召集 25 人专家组制定的睡眠日记标准，做记录功能**必须按这 9 项**，否则数据没有临床可比性：

1. 你几点上床？
2. 你几点**试着**入睡？
3. 你花了多久睡着？（睡眠潜伏期）
4. 夜里醒了几次？（不含最后一次）
5. 这些觉醒总共持续多久？（WASO）
6. 最后一次醒来是几点？
7. 你几点起床离开床？
8. 你如何评价昨晚的睡眠质量？（1–5 分）
9. 备注

派生指标：
```
TIB  卧床时间 = 起床时间 − 上床时间
TST  总睡眠时间 ≈ TIB − SOL − WASO
SE   睡眠效率 = TST / TIB × 100%   （健康成人 ≥85–90%）
```

补充要点（Vector Sleep Clinic / CBT-I 实践）：
- 只填 **1 周不够**，标准是 **2 周**（覆盖工作日与周末差异）
- **早上填，不要晚上填**（记忆新鲜）
- **不要看钟**，估算就行（看钟会加重失眠）
- **别跳过糟糕的夜晚**，那是最有价值的数据
- 用户**不应该自己解读**日记

## 3. 重点功能的详细设计

### 3.1 睡眠计算器（核心，但要做深）

**输入**：模式（就寝/起床）、基准时间、周期长度（默认 90，可调 70–120）、入睡潜伏期（默认 15）

**输出**：6 个候选时间点，按时间排序，标周期数与质量分档

**必须做的四件事**（否则和市面上没区别）：

1. **可调参数**：周期长度、潜伏期两个滑杆。市面 90% 的产品把 90 写死。
2. **结果旁挂解释**：每个候选时间点可展开——「这个点意味着 5 个完整周期、7.5 小时睡眠，且落在周期边界（浅睡段）」
3. **免责说明**：明确写「周期长度是个体化的，90 分钟是人群均值，中位数实际约 96 分钟；本结果用于规划而非预测」
4. **落点可视化**：用一条横向时间轴把 6 个候选画出来，而不是纯列表（LF 版用的是列表 + 绿色高亮，可以做得更好）

**边界处理**：跨零点、跨日、夏令时。

### 3.2 小睡规划器

**四档预设**（都标证据）：

| 时长 | 名称 | 说明 | 证据 |
|---|---|---|---|
| 20 min | 能量小睡 | 不进入深睡，醒来清爽 | B |
| 26 min | NASA 方案 | 含入睡缓冲；表现 +34%、警觉 +54% | B（Rosekind）|
| 60 min | 记忆巩固 | 含 SWS 与部分 REM，注意可能发懵 | B |
| 90 min | 完整周期 | 需留 20 分钟缓冲 | B |

**加一个「咖啡小睡」开关**：躺下前喝咖啡，20 分钟起效，醒来正好叠加。

**时间约束**：不晚于 15:00，附「太晚小睡会偷夜间睡眠压力」的说明。

### 3.3 咖啡因截止线（差异化强）

**交互**：选饮品（咖啡/茶/可乐/能量饮料/奶茶，含典型 mg 值）→ 选时间 → 选预计就寝时间 → 出结果

**输出**：
- 一条**衰减曲线**（x 轴时间，y 轴血中残留量），标出就寝时刻的残留值
- 判定：残留 < 50 mg 视为影响较小
- 结论文案：「你 14:00 的那杯美式，到 23:30 还有约 40 mg 在体内」

**必须体现的关键事实**：Drake 2013 —— 睡前 6 小时的 400mg 咖啡因让客观睡眠时间**减少 1 小时以上**，而**被试主观上感觉不到**。这条要作为产品内的科普卡。

**进阶**：半衰期可调（默认 5h，可切到慢代谢 9h / 孕妇 10h+）。

### 3.4 睡眠负债账本

**输入**：最近 N 天的实际睡眠时长（手输或从日记带出）、目标时长

**输出**：
- 债务总额（小时）
- **社会时差**：工作日与休息日的睡眠中点之差（>1h 提示，>2h 严重）
- 补觉计划：按「每晚多睡 1–1.5 小时」摊平，给具体天数

**两条必须写出来的反常识**：
1. **一晚补不回来**（Banks 2010：10 小时卧床仍未完全恢复）
2. **未恢复状态下再加债，损伤接近两倍**（Sleep Advances 2023）

### 3.5 睡前降速流水线（wind-down）

按 T-90/T-60/T-30/T-0 时间轴，每格给一条**当下就能做**的事：

| 时间 | 动作 | 依据 |
|---|---|---|
| T-120 min | 调暗环境光，换暖光 | 光抑制褪黑素 |
| T-90 min | 泡/冲热水澡（40–42.5℃，10–20 min） | Haghayegh 2019：平均缩短入睡 10 分钟 |
| T-60 min | 停止咖啡因/酒精/大量进食 | Drake 2013 / Gardiner 2025 |
| T-30 min | 把明天的待办写下来（卸载工作记忆） | 反刍是入睡障碍主因 |
| T-15 min | 认知洗牌 或 呼吸练习 | Beaudoin / 慢呼吸 |
| T-0 | 关灯；室温 18–20℃ | 核心体温需下降才能入睡 |

**注意**：这一块要**避免变成待办清单**——SleepKit 的经验是「睡前只填一个 yes/no」。所以流水线是「建议」不是「打卡」。

### 3.6 快速入睡工具箱

**认知洗牌引导器**（首选推荐，零成本、可交互）
- 内置词库（≥5 字母、少重复字母的中文词更合适，如「玻璃杯」「电视机」）
- 界面：大字号显示当前字母 → 展示该字母下的若干联想词 → 每 5–15 秒自动切换 → 用户不用操作，看着就行
- 附原理说明：失眠者睡前思维是担忧/计划/反刍，好睡眠者是梦样、非线性、视觉化

**呼吸引导器**
- 主推**极简版：呼气时长 = 吸气 ×2**（不需屏息，最易执行）
- 次选 4-7-8（**必须标注**：机制合理但缺大规模 RCT，网上流传的具体数字来源存疑）
- 附安全提示：哮喘/COPD 患者做屏息类练习前咨询医生

**温度模块**
- 泡澡倒计时（T-90 提醒）
- 卧室温度建议：成人 18–20℃，老年人 20–25℃
- 「冷脚可穿薄袜」这个反常识点单独做卡

### 3.7 睡眠日记（严格按标准）

**为什么必须按 Consensus Sleep Diary**：它是 AASM 专家组制定的字段标准，用户拿去给医生看是有意义的；自己发明字段就没这个价值。

**交互设计要点**：
- **早间填写**（首页早间卡片一键进入）
- **逐项问答式**，一屏一项，不要给一个大表格
- **时间用「滑杆 + 粗调」而非精确输入**，鼓励估算（看钟会加重失眠）
- 质量用 1–5 星
- 填完立刻给一个**描述性总结**（不是分数）：哪项好、哪项要注意

**计算与反馈**（借 iCANSleep 的算法）
```
SE = TST / TIB × 100
SE ≥ 85%  → 睡眠窗口 +30 min
75–85%   → 维持
SE < 75%  → 睡眠窗口 −30 min（下限 5 小时）
```
> 这个算法本身属于 CBT-I 的睡眠限制疗法，**属于干预手段**。建议 V1 只展示 SE 数值和趋势，**不自动给睡眠窗口指令**，避免越界成治疗方案。

### 3.8 知识与证据页（全站差异点）

**结构**：
- 每条结论一个卡片：**一句话结论 → 证据等级 → 具体数据 → 可执行动作 → 原始出处**
- 按主题分区：睡眠需求 / 熬夜恢复 / 饮食 / 作息节律 / 快速入睡
- 常见误区单开一页（**这是最容易被传播的内容**）

**误区清单**（都可直接做卡片）：
1. 睡眠必须是 90 分钟的整数倍 → 周期 70–120，中位数 96
2. 周末睡懒觉能补回来 → 一晚补不回，还会造成社会时差
3. 早睡一小时就能睡得更多 → 撞进禁睡区，反而更难睡
4. 我喝咖啡照样睡 → 主观感觉不可靠，客观减少 1 小时
5. 睡前喝酒助眠 → 低剂量就减少 REM
6. 手环测的睡眠分期很准 → 消费级设备准确率仅 70–80%
7. 蓝光眼镜能改善睡眠 → Cochrane 2023：证据极低，无法确定

├─ 咖啡因截止线

## 5. 关键流程

### 5.1 首次进入（借鉴 SomniBot 的「渐进式个性化」）

```
进入 → 一句话价值主张（带证据标签的样例卡片）
     ↓
3 问快速校准（不注册）：
  1. 你通常几点起床？
  2. 你躺下后一般多久睡着？（滑杆，默认 15 分钟）
  3. 你的年龄区间？（用于目标时长）
     ↓
立刻出结果：今日建议就寝时间 + 一个可执行动作
     ↓
「想更准？」→ 引导认识周期长度可调 / 建议记 3 天日记
```

**原则**：**先给价值，再要数据**。不要一上来就让人填 9 项日记。

### 5.2 单次使用（每日两次触达）

**早间（醒来后 5 分钟窗口）**
- 提示填昨晚日记（如果昨天记了）
- 给昨晚的解读 + 今天的一条建议

**睡前（就寝前 15 分钟窗口）**
- 显示今晚建议就寝时间（按当前时间实时算）
- 一键启动降速流水线 / 认知洗牌

这个「早间锚定 > 睡前提醒」的顺序是有依据的：睡眠 App 的留存文章分析指出，**睡前推送的发效最差**（用户在床上正开着 12 个 App），而**早间推送有具体产出可回应**（Oura 就是靠早间摘要撑起整个打开率）。

### 5.3 周复盘

- 一周趋势（TST / SE / SOL / 规律性）
- 描述性总结，**不给总分**（避免「睡眠表现焦虑」）
- 一条最值得改的事

## 6. 留存设计（睡眠 App 特有的坑）

这部分有专门的行业分析，结论很反直觉，值得单列：

### 6.1 结构性难题
**用户在产品最被需要的时候是失去意识的。** 有效触达窗口只有「睡前 15 分钟 + 醒后 5 分钟」。所以产品必须把价值压缩进这两个窗口，或者提供睡眠时间之外可用的内容（Headspace 用冥想、Calm 用每日内容来撑）。

### 6.2 羞耻循环（shame loop）
睡眠 App 的流失模式很特殊：用户因为睡不着才下载 → 中断两晚 → 看到「连续记录」断了 → **觉得已经失败了** → 卸载。

因此：
- **不要做「连胜」，或者前 14 天不显示连胜**，改成「已记录 N 晚」这种中性计数
- 中断后的召回文案**绝对不要提连胜，也不要提供付费「补签」**——这在养成类产品有效，在健康类产品会**重新唤起失败感**
- 正确文案方向：「大家都有难睡的晚上，你的数据还在，接着记就行」

### 6.3 用「身份认同」代替「习惯」
从「我在努力睡得更好」→「我是一个把睡眠当作恢复优先项的人」。
具体做法：7 天后给用户一个**睡眠人格标签**（如「晚相位型——你的身体天然比平均晚 90 分钟达到峰值」）。这种描述会变成用户自我描述的一部分。

### 6.4 里程碑要有叙事
不要只显示「连续 30 天」徽章，改成「你连续 30 晚保护了自己的恢复窗口」。具体化让成就显得是挣来的。

### 6.5 数据要连到昨天做了什么
早间洞察必须是 2–3 句**个性化解读**，而且要连到昨天的行为（咖啡因、运动、屏幕、就寝时间），而不是又一个分数。

### 6.6 诚实边界
不要承诺「治愈失眠」。文献里已经明确：**光靠睡眠卫生（戒咖啡、换床垫）不足以治疗慢性失眠**。把这个诚实写出来，反而是信任资产。

## 9. 明确不做（重复强调，因为很容易走着走着就跑偏）

| 不做 | 理由 |
|---|---|
| 白噪音/冥想音频 | 红海、存储版权成本、证据只有 B/C |
| 睡眠监测（麦克风/手环） | 静态站做不到；手机方案精度仅 70–80% |
| 睡眠阶段图 | 没有真传感器数据就是在编 |
| 睡眠总分 | 会引发「睡眠表现焦虑」，且科学上站不住 |
| 连胜机制 | 羞耻循环，是这类产品最大的流失源 |
| 医疗建议 | 越界；慢性失眠指向 CBT-I 与就医 |
| 社区 | 监管成本高 |

## 10. 一句话总结设计原则

> **不制造数据，只做解释和时机。**
> 用户缺的从来不是睡眠数据，是「我现在该做什么」和「为什么」。
